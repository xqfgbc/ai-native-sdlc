# Architecture guardrails

Skills are advisory; **ArchUnit tests are the deterministic layer** that fails
the build when an agent breaks the architecture. Every service ships an
`ArchitectureTest` generated by `scripts/new-service-repo.sh`.

## Rules that must hold (enforced by ArchUnit)

1. **Layering** — `api` may use `core` and DSL/DTO types; `core` may use
   `adapters`; `api` must **not** call `adapters` directly.
2. **No web in core** — `core` may not import `org.springframework.web..`,
   `org.springframework.http..`, `jakarta.servlet..`, or `reactive`.
3. **Controller placement** — `@RestController` classes live in `..api..`.
4. **Entity placement** — `@Entity` classes live in `..adapters.persistence..`
   and never leak to `api`/`core`.
5. **No field injection** — no `@Autowired`/`@Resource`/`@Inject` on fields;
   constructor injection only.
6. **No package cycles** — top-level feature packages are cycle-free.
7. **`@Transactional` is public** — transactional methods are public (proxy
   rule; private/final silently do nothing).
8. **No legacy time** — no dependency on `java.util.Date`; use `Instant` /
   `OffsetDateTime`.
9. **Entities are not Lombok `@Data`** — no `@Data`/`@EqualsAndHashCode` on
   `@Entity`.

## Where it lives and how it runs

- Generated at `src/test/java/<pkg>/ArchitectureTest.java`.
- Run with `./gradlew test` (also part of `make test`).
- A violation fails the build — it is not a review opinion, it is a gate.

## Interpreting a failure

Read the ArchUnit message: it names the offending class and rule. Fix the
**code** (move the class, invert the dependency, use constructor injection);
never weaken or delete a rule to make it pass — changes to the rule set are a
platform-team PR.

## Optional next step: Spring Modulith

If the service moves to package-by-feature, add
`org.springframework.modulith:spring-modulith-starter-test` and `@ApplicationModule`
boundaries; `ApplicationModules.of(App.class).verify()` replaces the layering
slice rules. See the `spring-service-conventions` skill for the module layout.
