# Agent splitting standard（poteto：几个教好的 Bot 比一大群有用）

## 什么时候才拆一个新 agent

**只有当"目标 / 工具 / 工作方式 / 审批要求"明显不同时才拆**。至少满足两条：

| 维度 | 拆分的信号 | 不拆的信号 |
|---|---|---|
| 目标 | 一个"扫描找问题"，一个"修复问题" | 同一个人做同一类事的不同步骤 |
| 工具 | 需要只读工具 vs 需要写 + Bash | 只是多读几个文件 |
| 工作方式 | 可并行、独立上下文、不同模型族 | 强顺序依赖、共享上下文 |
| 审批/权限 | 只读 / 能写 / 能合并 权限不同 | 权限相同 |

**反例**：把"写单测"和"写业务代码"拆成两个 agent，但目标/工具/权限几乎一样 → 应该是一个 agent + 两个 skill。

## 当前子代理（8 个）与理由

| Agent | 目标 | 工具/权限 | 为什么独立 |
|---|---|---|---|
| `verifier` | 独立验证 exact patch | 只读 + 跑测试 | 作者不能自批（分离职责） |
| `security-auditor` | 安全审计 | 只读 | 与功能 reviewer 目标不同 |
| `pr-reviewer` | 三遍评审 | 只读 | 审核者角色 |
| `code-simplifier` | 简化 diff | 可写（仅简化） | 目标=可读性，与功能修复不同 |
| `codebase-researcher` | 定位代码/事实 | 只读 + grep | 探索性、可并行 |
| `spec-reviewer` | 评审 spec | 只读 | 门禁在 spec 阶段 |
| `architect` | 架构/技术选型 | 只读 | 跨服务/长期判断 |
| `scanner` | **只扫不改**，追加 findings | 只读，禁止写 `src/**` | 建立"问题队列"而非逐条修复；队列逼出根因 |

## 什么时候合并 / 删掉

- 两个 agent 的"触发条件 + 权限 + 输出物"几乎相同 → 合并，用 skill 区分。
- 某个 agent 连续一个季度没有触发记录 → 删除（宁少勿多）。
- 新增 agent 前先问：**能不能用现有 agent + 一个新 skill 解决？** 能，就不加。

## 配套

- 每个 agent 必须有：触发表、权限边界、输出物、失败时怎么办。
- 章节见 `AGENTS.md` §5；适配见 `docs/agent-support-matrix.md`。
